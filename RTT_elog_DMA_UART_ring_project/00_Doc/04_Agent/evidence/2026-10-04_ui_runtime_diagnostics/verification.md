# UI 运行时资源测试（2026-10-04）

状态：本轮测量完成；临时固件已恢复为 v1.1.1，下载校验通过。正式业务代码及版本归档没有改动，用户已授权提交推送本次测试记录。

## 方法与场景

用户授权临时诊断固件。独立 Keil 工程位于忽略的 `06_Output/Build/ui_runtime_diagnostics/`；只替换平台 GUI 单元为诊断副本，其余输入复用 v1.1.1；完整构建 0 errors / 380 warnings。诊断源码快照附于本目录，仅是证据，不参与正式构建。

- Display Task 在 LVGL 服务完成后每秒调用 lv_mem_monitor；FreeRTOS 栈高水位查询针对当前 Display Task，单位已从 StackType_t 转换为字节。
- DWT CYCCNT 在 GUI 初始化时启用，SystemCoreClock=100 MHz；记录单次同步 SPI flush 和 lv_timer_handler 整次调用的周期最大值。计时包含抢占与中断；资源采样在计时区间之外。
- 每秒通过 J-Link DLL 读取 volatile 快照，以序号校验稳定性；不调用 halt、reset、断点或目标函数。连接后及采样中检查 CPU 未暂停。
- 共 122 个快照，连续观测约 121.39 秒；首个快照为开机约 49.147 秒，最后为约 170.514 秒。启动阶段不在逐秒原始日志中，但固件历史峰值/最大值从初始化开始累计。
- 用户按提示完成 10 次 ONCE，确认均正常；随后确认持续采集场景页面正常。收尾串口实际为 RUNNING，因此不将长按 STOP 后进入 STOPPED 写为通过，也不把屏幕反馈时延当作本次计时指标。

## 判断与下一步

当前场景没有资源耗尽迹象，短时采样空闲和最大连续块稳定。仍保留 24 KiB LVGL 池、6 KiB Display 栈及 28 KiB RTOS heap，不因本次短测试直接下调预算。

后续优先检查未变化文本导致的重绘和重复样式；若要缩减内存池或绘制缓冲，逐项调整并复测启动、ONCE、持续采集与状态切换。长时间碎片、故障注入和触摸端到端时延仍未测。
