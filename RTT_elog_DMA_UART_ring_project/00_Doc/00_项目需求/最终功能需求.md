# 最终功能需求

## 1. 文档目的

本文档用于收束 `stm32f4_DMA_UART_ring_RTOS` 项目的最终综合实现范围，作为 GPIO、软件 I2C、传感器、按键事件、APP 状态机、日志及串口联调的统一功能基线。

本阶段不继续扩展 SPI/LCD、外部 Flash 等外围功能，优先完成一个可稳定运行、可通过本地按键和 PC 串口指令控制的数据采集闭环。

---

## 2. 最终硬件组成

- MCU：STM32F411CEU6；
- 温湿度传感器：DHT20；
- 六轴惯性传感器：MPU6050；
- 用户按键：PA0；
- 状态 LED：PC13；
- PC：通过 UART 串口助手控制与数据显示；
- DHT20 与 MPU6050 共用 PB6/PB7 Software I2C。

Software I2C 基于 Platform GPIO，不使用 STM32 硬件 I2C 外设。

---

## 3. 系统默认状态

系统启动并完成初始化后：

```text
Acquisition = STOPPED
LED         = OFF
UART RX     = ACTIVE
RTT Log     = ACTIVE
```

- DHT20 / MPU6050 不进行周期采集；
- UART 接收功能保持工作；
- RTT / EasyLogger 保持工作；
- APP 层是 STOPPED / RUNNING 的唯一真实状态源。

---

## 4. 按键控制需求

### 4.1 单击

STOPPED：

```text
SINGLE
 -> APP_CTRL_START
 -> RUNNING
 -> LED ON
 -> start periodic acquisition/report
```

RUNNING：保持 RUNNING，不重复启动。

### 4.2 长按

RUNNING 状态长按 >= 3 s：

```text
LONG
 -> APP_CTRL_STOP
 -> STOPPED
 -> stop periodic acquisition/report
 -> LED OFF
```

STOPPED 下长按无额外业务动作。

### 4.3 双击

STOPPED：

```text
DOUBLE
 -> APP_CTRL_SAMPLE_ONCE
 -> DHT20 sample once
 -> MPU6050 sample once
 -> UART report once
 -> UART TX success
 -> LED blink 3 times
 -> LED OFF
 -> remain STOPPED
```

RUNNING 下双击不执行额外单次采集。

若传感器采集失败或 UART 发送失败，则不执行成功闪烁，并通过 RTT 记录异常。

### 4.4 手势参数

第一阶段：

```text
PROJECT_BUTTON_SAMPLE_PERIOD_MS = 10 ms
PROJECT_BUTTON_DEBOUNCE_MS = 30 ms
PROJECT_BUTTON_DOUBLE_CLICK_MS = 300 ms
PROJECT_BUTTON_LONG_PRESS_MS = 3000 ms
```

单击必须等待双击窗口结束后再确认。

---

## 5. LED 状态需求

```text
STOPPED                -> OFF
RUNNING                -> ON
RUNNING periodic TX    -> keep ON
ONCE TX SUCCESS        -> blink 3 times -> OFF
ONCE sample/TX failure -> keep OFF
```

成功闪烁节奏第一版：

```text
100 ms ON / 100 ms OFF / 3 times
```

APP 表达业务语义，不直接处理 LED 有效电平。

---

## 6. UART 控制需求

第一阶段命令：

```text
START\r\n
STOP\r\n
ONCE\r\n
STATUS\r\n
HELP\r\n
```

行为：

| 命令 | STOPPED | RUNNING |
| --- | --- | --- |
| START | 进入 RUNNING | 保持 RUNNING，返回 already running |
| STOP | 保持 STOPPED，返回 already stopped | 进入 STOPPED |
| ONCE | 单次采集并发送，保持 STOPPED | 不额外采样，返回 already running |
| STATUS | 返回 STOPPED | 返回 RUNNING |
| HELP | 返回命令列表 | 返回命令列表 |

UART Service 不直接维护 APP 状态，不直接控制 LED 或传感器。

---

## 7. 控制事件统一原则

按键和 UART 统一转换为：

```text
APP_CTRL_START
APP_CTRL_STOP
APP_CTRL_SAMPLE_ONCE
APP_CTRL_GET_STATUS
```

最终是否执行由 APP Control FSM 决定。

---

## 8. 传感器采集需求

### 8.1 周期采集

第一阶段将“完整采集周期”和“UART 上报周期”统一为：

```text
2000 ms / 2 s
PROJECT_ACQUISITION_PERIOD_MS = 2000U
```

RUNNING 每 2 s：

```text
DHT20 read once
 -> MPU6050 read once
 -> organize one business report
 -> UART send
 -> RTT DEBUG summary
```

STOPPED 不进行周期采集。

DHT20 规格书建议约每 2 秒测量 1 次，以降低频繁激活造成的自热影响，因此 2 s 作为第一阶段统一周期。

### 8.2 DHT20

采集：

```text
temperature
relative humidity
```

DHT20 第一阶段正式实现为 Platform device capability，不单独建立空转发 Service。后续统一 Acquisition Service 再负责跨 DHT20 + MPU6050 的采集语义。

### 8.3 MPU6050

第一阶段采集：

```text
Accel X/Y/Z
Gyro X/Y/Z
```

建议同时保留 raw，并提供基础换算：

```text
Accel raw -> g
Gyro raw -> deg/s
```

第一阶段不实现：

```text
Roll
Pitch
Yaw
Complementary Filter
Kalman Filter
DMP
复杂姿态融合
```

---

## 9. Software I2C 需求

Software I2C 已完成并冻结，基于 Platform GPIO。

能力包括：

```text
START / STOP
ACK / NACK
Byte Write / Read
multi-byte write/read
Repeated START write-read
7-bit address
microsecond timing
```

DHT20 与 MPU6050 共用同一总线。

第一阶段优先由单一 Acquisition 执行上下文串行访问两个设备；只有未来出现多个真实访问者时，才增加 transaction-level mutex。

## 10. DHT20 Phase 6 需求

正式设计：

```text
00_Doc/02_架构设计/DHT20_Phase1设计.md
```

正式模块：

```text
03_Platform/platform_bsp/dht20/platform_dht20.h
03_Platform/platform_bsp/dht20/platform_dht20.c
```

第一版公共 API：

```text
platform_dht20_init()
platform_dht20_read()
platform_dht20_deinit()
```

关键协议：

```text
7-bit address = 0x38
write AC 33 00
STOP
wait >= 80 ms
new START
read 7 bytes
ACK first 6 bytes
NACK final CRC byte
STOP
```

必须验证：

```text
Busy
frame CRC8
OTP CRC_flag
CalibrationEnable
20-bit RH raw
20-bit T raw
float RH/T conversion
```

失败时不得把半成品 measurement 作为成功数据返回。

DHT20 只引用共享 `platform_i2c_t`，deinit 不得关闭共享 I2C。

## 11. 数据发送需求

传感器数据必须复用现有：

```text
APP / Communication
 -> UART Service
 -> Platform UART
 -> STM32 UART Impl
 -> DMA
 -> USART1
 -> PC Serial Assistant
```

不得另建旁路 UART 发送通道。

第一阶段文本格式例如：

```text
ENV,T=25.34,H=62.18\r\n
IMU,AX=0.013,AY=-0.021,AZ=0.998,GX=0.12,GY=-0.42,GZ=0.08\r\n
```

RUNNING 每 2 s 发送一次完整报告。

---

## 12. RTT / EasyLogger 日志需求

职责：

```text
UART -> 产品/业务数据与控制
RTT  -> 初始化、运行状态、采集状态、诊断与异常
```

日志等级建议：

```text
INFO  -> initialization / START / STOP / ONCE / state change
DEBUG -> 2 s acquisition summary / report send state
WARN  -> recoverable I2C / Sensor / UART issue
ERROR -> initialization / critical operation failure
```

正常运行不逐 I2C bit / ACK、不逐 UART byte、不逐 DMA 步骤刷日志。

ISR / HAL Callback 不进行大量格式化日志。

---

## 13. 推荐任务组织

第一阶段方向：

```text
Communication Task
Acquisition Task
Indicator Task
```

不为 DHT20 和 MPU6050 各建独立 Task。

永久 Button processing context、IPC、priority、stack 在后续 RTOS Phase 冻结。

---

## 14. 分层边界

```text
APP
- 产品状态 / 控制决策 / 周期编排

Service
- UART / Log / Indicator / Button gesture / future Acquisition semantics

Platform
- UART / GPIO / OS / Log / Software I2C / LED / Button / DHT20 / MPU6050 capability

Impl
- STM32 / FreeRTOS / Middleware concrete implementation

Vendor
- HAL / CMSIS / FreeRTOS / EasyLogger / RTT
```

固定依赖：

```text
APP -> Service       ALLOWED
APP -> Platform      ALLOWED
Service -> Platform  ALLOWED
Platform -> Impl     ALLOWED
APP -> Impl          FORBIDDEN
Service -> Impl      FORBIDDEN
```

## 15. 第一阶段范围冻结

必须完成：

- GPIO Platform / Impl；
- LED；
- Platform Button / Button Service；
- Software I2C；
- DHT20；
- MPU6050 basic 6-axis；
- APP Control FSM；
- UART `START / STOP / ONCE / STATUS / HELP`；
- RUNNING 每 2 s 完整采集并发送；
- ONCE TX success 后 LED 闪 3 次；
- RTT / EasyLogger 诊断；
- 最终综合实板验证。

当前暂停：

```text
SPI / LCD / GUI
W25Q64
AT24C02
Bluetooth
Roll / Pitch / Yaw
DMP / filters
复杂二进制 UART protocol
Button EXTI / low-power wake
```

## 16. 最终验收场景

### 场景 1：启动

- 上电初始化成功；
- RTT 可观察主要模块状态；
- STOPPED；
- LED OFF；
- UART RX ACTIVE；
- 不周期发送传感器数据。

### 场景 2：按键启动

- STOPPED 单击；
- RUNNING；
- LED ON；
- 每 2 s 采集 DHT20 + MPU6050；
- 每 2 s PC 收到一组数据。

### 场景 3：按键停止

- RUNNING 长按 >= 3 s；
- STOPPED；
- 周期采集停止；
- LED OFF。

### 场景 4：按键单次采样

- STOPPED 双击；
- 两个传感器各采集一次；
- PC 收到一次完整数据；
- TX 成功后 LED 闪 3 次；
- 保持 STOPPED。

### 场景 5：UART 控制

- `START / STOP / ONCE / STATUS / HELP` 正确；
- UART 和 Button 使用同一个 APP 状态源。

### 场景 6：异常

以下异常必须可通过 RTT 观察，不得静默失败：

```text
I2C NACK / bus failure
DHT20 status / CRC failure
MPU6050 WHO_AM_I / read failure
UART / DMA failure
RingBuffer overflow
```

ONCE 失败时不得执行成功闪烁。

## 17. DHT20 Phase 6 板测要求

采用：

```text
RTT / EasyLogger
+
Logic Analyzer
```

逻辑分析仪连接：

```text
PB6 = SCL
PB7 = SDA
```

单次测量应观察到：

```text
START
0x70 + ACK
0xAC + ACK
0x33 + ACK
0x00 + ACK
STOP

>= 80 ms

START
0x71 + ACK
7-byte read
ACK first 6 bytes
NACK final CRC byte
STOP
```

并验证约 2 s 连续读取时事务稳定。

## 18. 项目最终闭环

```text
KEY -------------------------+
                              |
                              v
                       APP Control FSM
                              ^
                              |
PC -> UART RX -> RingBuffer -> Command Parser
                              |
                              v
                      Acquisition Task
                       every 2 seconds
                         /         \
                      DHT20       MPU6050
                         \         /
                          Soft I2C
                              |
                        Platform GPIO

Sensor Data
 -> UART Service
 -> UART DMA TX
 -> PC Serial Assistant

Runtime / Errors
 -> EasyLogger
 -> RTT
```

完成上述闭环后，本项目核心目标视为完成。SPI/LCD、姿态解算等作为后续独立扩展，不纳入当前最终验收。
