# MPU6050 数据手册项目适用分析

> 适用项目：`stm32f4_DMA_UART_ring_RTOS`  
> 平台：STM32F411CEU6 + FreeRTOS + 软件 I2C  
> 范围：MPU6050 六轴基础数据采集；不包含姿态解算、DMP、FIFO 数据流和 MPU6050 中断驱动。

## 1. 本项目需要 MPU6050 做什么

本项目的 MPU6050 是“运动数据快照”设备，而不是实时姿态系统：

- 系统处于 `RUNNING` 时，由 APP 的采集执行上下文每 `5 s` 读取一次六轴数据；
- 系统处于 `STOPPED` 时，双击或 `ONCE` 命令读取一次；
- 读取加速度 `AX/AY/AZ` 和角速度 `GX/GY/GZ`，组织为文本后复用既有 UART DMA TX 链路发送至 PC；
- RTT + EasyLogger 仅记录初始化结果、失败和必要的采样摘要；不在软件 I2C 位/字节级路径中打印日志。

因此，首版只需完成：设备地址、`WHO_AM_I` 验证、唤醒与基础量程配置、连续读取 14 字节数据块、原始值/物理量转换及错误上报。

## 2. 与当前架构的对应关系

```text
APP 采集/控制上下文
    -> MPU6050 Motion 模块（初始化、寄存器配置、数据转换）
    -> Platform I2C（同步 write / write_read 事务）
    -> Platform GPIO（开漏 SCL/SDA）
    -> STM32 GPIO Impl
```

MPU6050 模块不得直接调用 `HAL_GPIO_xxx`、CubeMX Handle 或 FreeRTOS 具体 Handle。现有 `platform_i2c_*` 接口的地址参数是 **7 位 I2C 地址**，且 `platform_i2c_write_read()` 已保证“写寄存器地址 → Repeated START → 读数据”的完整同步事务。

DHT20 与 MPU6050 共用同一条软件 I2C 总线。第一阶段由同一个采集执行上下文顺序访问两者，因而不增加 mutex；若以后出现多个真实访问任务，mutex 必须覆盖一整个 I2C transaction，不能只锁单个字节或 START/STOP。

## 3. 必须掌握的总线信息

| 项目 | 结论 | 对本项目的意义 |
| --- | --- | --- |
| 从地址 | AD0 为低时通常为 `0x68`，为高时通常为 `0x69` | 配置和调用中传入 7 位值 `0x68/0x69`，不能传 `0xD0/0xD1` |
| 线上地址字节 | `0x68` 对应写 `0xD0`、读 `0xD1`；`0x69` 对应写 `0xD2`、读 `0xD3` | 逻辑分析仪可据此确认地址和 R/W 位 |
| `WHO_AM_I` | 寄存器 `0x75`，参考文件给出的默认值为 `0x68` | 初始化时必须读回校验；不匹配时不上报伪造数据 |
| 寄存器读取 | 先写寄存器地址，再 Repeated START 读数据 | 使用 `platform_i2c_write_read()`，不要拆为独立 write/read |
| 软件 I2C 时序 | 位级时序依赖微秒延时、开漏释放高电平和 SCL 实际拉高检测 | 不得用 `osDelay()`、`vTaskDelay()` 实现 bit-level 时序 |

> `WHO_AM_I=0x68` 是所给寄存器手册的结论；实际模块的 AD0 电平仍应按原理图/板级连接确认。地址 NACK 是“地址错误、模块未上电或总线异常”的诊断起点，不应静默换地址后继续运行。

## 4. 首版真正需要的寄存器

| 寄存器 | 地址 | 首版建议 | 作用与理由 |
| --- | ---: | ---: | --- |
| `WHO_AM_I` | `0x75` | 只读并校验 `0x68` | 确认目标设备可通信 |
| `PWR_MGMT_1` | `0x6B` | 写 `0x01` | 清除 `SLEEP`，选择 X 轴陀螺 PLL 时钟；比上电后的内部时钟更稳定 |
| `SMPLRT_DIV` | `0x19` | 可写 `0x04` | DLPF 开启时输出采样率为 `1000/(1+4)=200 Hz`；项目虽每 5 s 才取一次，但保持内部稳定更新 |
| `CONFIG` | `0x1A` | 可写 `0x03` | `DLPF_CFG=3`，加速度约 44 Hz、陀螺约 42 Hz，适合低频运动快照并抑制高频抖动 |
| `GYRO_CONFIG` | `0x1B` | 写 `0x00` | `FS_SEL=0`，量程 ±250 °/s，首版获得最高灵敏度 |
| `ACCEL_CONFIG` | `0x1C` | 写 `0x00` | `AFS_SEL=0`，量程 ±2 g，首版获得最高灵敏度 |
| `ACCEL_XOUT_H` | `0x3B` | 从此连续读 14 字节 | 一次得到加速度、温度、陀螺数据，保证同一采样快照 |
| `INT_ENABLE` | `0x38` | 保持默认 `0x00` | 首版用 5 s 任务调度，不启用 DATA_RDY 中断 |
| `FIFO_EN` / `USER_CTRL` | `0x23` / `0x6A` | 不启用 | FIFO 溢出会丢失旧数据；本项目不需要高频积压数据流 |

`PWR_MGMT_2`、低功耗 cycle、单轴 standby、`INT_STATUS`、FIFO 和辅助 I2C 主机模式都属于后续扩展能力，当前没有业务价值。尤其不要设置 `USER_CTRL.I2C_IF_DIS`；参考文件明确 MPU6050 应始终写 0。

## 5. 建议的初始化顺序

初始化和周期采集均在任务上下文执行，不能在 GPIO EXTI、UART DMA Callback 或任何 ISR 中执行。

```text
1. 初始化/确认共享 Platform I2C 总线可用
2. 以配置的 7 位地址读 WHO_AM_I (0x75)，校验为 0x68
3. 写 PWR_MGMT_1 (0x6B) = 0x01，退出睡眠并选择 PLL 时钟
4. 写 CONFIG (0x1A) = 0x03
5. 写 SMPLRT_DIV (0x19) = 0x04
6. 写 GYRO_CONFIG (0x1B) = 0x00
7. 写 ACCEL_CONFIG (0x1C) = 0x00
8. 记录“MPU6050 初始化成功”；任何一步失败则返回明确错误并保留 STOPPED/RUNNING 的业务状态决定权给 APP
```

以上 `0x03 / 0x04 / 0x00 / 0x00` 是首版可读、可验证的推荐配置，不是不可变硬件常数。若产品实际运动幅度超过 ±2 g 或 ±250 °/s，应在专项设计中同时调整量程和第 7 节的换算系数。

## 6. 六轴数据读取与 I2C 事务

一次读取的寄存器范围为 `0x3B` 到 `0x48`，共 14 字节：

```text
0..1   ACCEL_XOUT_H/L
2..3   ACCEL_YOUT_H/L
4..5   ACCEL_ZOUT_H/L
6..7   TEMP_OUT_H/L
8..9   GYRO_XOUT_H/L
10..11 GYRO_YOUT_H/L
12..13 GYRO_ZOUT_H/L
```

事务语义应为：

```text
START -> (addr << 1 | W) -> ACK -> 0x3B -> ACK
      -> Repeated START -> (addr << 1 | R) -> ACK
      -> 连续读取 14 Byte（前 13 Byte 回复 ACK，最后 1 Byte 回复 NACK） -> STOP
```

这正是现有 `platform_i2c_write_read(i2c, address, &reg, 1, raw, 14)` 应承载的事务。手册说明传感器数据的用户可读寄存器会在串行接口空闲时镜像内部数据；因此对该连续区域做 burst read 能取到同一采样时刻的完整六轴快照，优于逐寄存器单字节读取。

## 7. 数据解释和 UART 文本输出

每个轴均为 **高字节在前的 16 位二补码有符号数**。先拼为 `int16_t` 原始值，再按当前量程换算；不能把两个字节当无符号数相加。

推荐初始量程为 ±2 g、±250 °/s，对应：

```text
accel_g  = accel_raw / 16384.0
gyro_dps = gyro_raw  / 131.0
```

其他量程的系数如下：

| 配置 | 加速度灵敏度 | 陀螺灵敏度 |
| --- | ---: | ---: |
| ±2 g / ±250 °/s | 16384 LSB/g | 131 LSB/(°/s) |
| ±4 g / ±500 °/s | 8192 LSB/g | 65.5 LSB/(°/s) |
| ±8 g / ±1000 °/s | 4096 LSB/g | 32.8 LSB/(°/s) |
| ±16 g / ±2000 °/s | 2048 LSB/g | 16.4 LSB/(°/s) |

本项目已经有 DHT20，MPU6050 内部温度 `TEMP_OUT` 不属于首版业务输出；如调试时需要，公式为：

```text
temperature_c = temp_raw / 340.0 + 36.53
```

建议的业务输出格式保持与项目需求一致：

```text
IMU,AX=0.013,AY=-0.021,AZ=0.998,GX=0.12,GY=-0.42,GZ=0.08\r\n
```

格式化结果必须保存在符合既有 UART 异步 TX buffer 生命周期合同的静态或调用者拥有缓冲区中，直至 TX Complete / Error；不能把即将退出作用域的栈缓冲区交给 DMA。

## 8. FreeRTOS 与错误处理边界

- I2C 总线访问是同步、会占用 CPU 的微秒级 GPIO 操作，只允许由采集/控制任务调用；它不是 ISR 服务。
- `vTaskDelay()` / 软件定时器用于 5 s 周期、按键时间窗和 LED 闪烁；只能用于任务级业务时间，不可用于 I2C bit 时序。
- `platform_i2c_write_read()` 成功后再转换数据；失败时本次采集失败，不发送伪造的上一帧数据。
- 地址 NACK 映射为设备未找到/地址或供电异常；数据 NACK、GPIO I/O 失败映射为通信错误；SCL 释放后未实际变高映射为超时。APP/Service 在任务上下文统计并通过 RTT 输出一次可诊断日志。
- 禁止在 I2C 位级循环、UART/DMA Callback 中格式化日志；否则会破坏时序或放大系统抖动。

## 9. 验证清单

1. 逻辑分析仪确认 SCL/SDA 空闲均为高、START/STOP 正确、地址字节和 ACK 正确，读事务存在 Repeated START，最后一个读字节后为 NACK。
2. 读取 `WHO_AM_I`：AD0 低的常见连接下应读到 `0x68`；若地址 NACK，先检查模块电源、共地、上拉、AD0 与引脚绑定，不要先改业务代码。
3. 静止平放时，三个陀螺轴应接近零但允许存在零偏；加速度某一轴应接近 ±1 g，具体正负由模块安装方向决定。
4. 翻转或旋转模块时，相关加速度/角速度轴的符号和幅度应发生合理变化；这验证字节序、符号转换和安装方向，而非姿态算法。
5. 在 `RUNNING` 下连续运行，确认每 5 s 一帧；在 `STOPPED` 下不发生周期读取；`ONCE` 成功上报且 UART 真正发送完成后才触发 LED 三闪。
6. 注入地址 NACK、拔掉模块或拉低总线，确认任务不死锁、RTT 有单次错误记录、DHT20/MPU6050 共享总线后续仍可恢复。

## 10. 首版明确不做的内容

以下功能虽然在 MPU6050 寄存器表中存在，但不属于当前验收范围：

- DATA_RDY 外部中断与 `INT_STATUS` 驱动采样；
- FIFO、FIFO overflow、DMP、辅助 I2C master；
- Roll / Pitch / Yaw、互补滤波、Kalman 滤波；
- 单独 MPU6050 采集任务、为传感器增加动态内存或复杂事件框架；
- 通过硬件 I2C 外设替换已经验证的软件 I2C。

保持这一范围，才能把本阶段验收聚焦在“共享软件 I2C 下稳定读取六轴快照，并通过 FreeRTOS 业务闭环可靠上报”。
