# P169H002（ST7789T3）显示接入使用文档

## 1. 目标与范围

本文件说明如何把开发板上已经接好的 P169H002-CTP 屏幕用于显示本工程的传感器数据。目标 MCU 为 `STM32F411CEU6`，工程为 `RTT_elog_DMA_UART_ring_project`。

本次只接入 **LCD 显示链路**：SPI、复位、数据/命令、片选和背光。**不接入、不初始化、不编译触摸相关的 I2C、复位和中断功能。**

屏幕的关键参数如下：

| 项目 | 值 |
| --- | --- |
| 模组 | P169H002-CTP |
| 控制器 | ST7789T3 |
| 可视分辨率 | 240 x 280 |
| 显示接口 | 4-wire SPI（仅需 SCK、MOSI、CS、DC） |
| 像素格式 | RGB565，2 字节/像素 |
| 显示坐标偏移 | `X_OFFSET = 0`，`Y_OFFSET = 20`（来自可运行参考驱动） |

> 注意：`P169H002-CTP NEW 规格书SPEC.md` 的原始 FPC 电气参数包含 `VDD=3.0V`、`VDDIO=1.8V` 与 `LEDK`。本开发板接的是屏幕连接器/模组接口，参考接线说明写的是模组 `VCC=3.3V`。因此只能按开发板已经设计好的连接器供电；不要把 3.3V 直接接到裸屏 FPC 的 VDDIO 或 LEDK。

## 2. 本开发板的实际连线

以下映射以开发板原理图片为准，不采用参考工程 `OV_Watch` 的 PB3/PB5/PB7 等示例引脚。

| MCU 引脚 | 板级网络 | 屏幕功能 | CubeMX 配置 |
| --- | --- | --- | --- |
| PA4 | `LCD_CS` | 片选 | GPIO 输出，初始高 |
| PA5 | `LCD_CLK` | SPI1 SCK | SPI1 SCK，AF5 |
| PA6 | `LCD_DC` | 命令/数据选择 | GPIO 输出，初始高 |
| PA7 | `LCD_MOSI` | SPI1 MOSI | SPI1 MOSI，AF5 |
| PB10 | `LCD_RST` | 硬件复位 | GPIO 输出，初始高 |
| PA1 | 图中 `LCD_BLCAK` / 连接器 `LCD_BACK_LIGHT` | 背光控制 | 先用 GPIO 输出；确认极性后可改为 TIM5_CH2 PWM |

连接器图中 LCD 相关引脚为：8=`LCD_RST`、9=`LCD_MOSI`、10=`LCD_CLK`、11=`LCD_CS`、12=`LCD_DC`、17=`LCD_BACK_LIGHT`。图中 `LCD_BLCAK` 与 `LCD_BACK_LIGHT` 的拼写不一致，但它们是同一条 PA1 背光控制链路，后续原理图命名应统一。

本次保持未使用的触摸引脚不变：PB2=`TP_INT`、PA15=`TP_RST`、PA8=`TP_SCL`、PB4=`TP_SDA`。它们不应出现在 LCD 驱动、CubeMX 外设或 Keil 编译组中。

## 3. 现有工程约束与接入结论

当前 `.ioc` 只启用了 GPIO、DMA、FreeRTOS 和 USART1，`HAL_SPI_MODULE_ENABLED` 仍被注释，工程中不存在 SPI Platform/Impl 模块。USART1 已占用：

| DMA 流 | 当前用途 | 是否可给 SPI1 TX 使用 |
| --- | --- | --- |
| DMA2 Stream2 | USART1_RX，循环接收 | 不可 |
| DMA2 Stream7 | USART1_TX | 不可 |
| DMA2 Stream3（Channel 3） | 未使用 | 推荐作为后续 SPI1_TX DMA 候选 |

参考工程 `OV_Watch` 把 SPI1_TX 放在 DMA2 Stream2；这会和本工程的 USART1_RX 冲突，不能直接复制。第一版显示驱动先采用阻塞式 `HAL_SPI_Transmit()`，完成颜色和文字自检后，再增加 SPI1_TX DMA。

不要复制参考文件中的以下做法：

- 不要把 `OV_Watch/BSP/TOUCH/` 或 `CST816.*` 加入工程。
- 不要在 `LCD_Color_Fill()` 中运行时改写 `hspi1.Init.DataSize` 或直接修改 `SPI->CR1`；该实现同时忙等 DMA 完成，不适合当前 RTOS 工程。
- 不要使用全屏帧缓冲。`240 x 280 x 2 = 134400` 字节，接近或超过本芯片可安全分配给应用的 SRAM。只使用一行 `240 x 2 = 480` 字节的静态 RGB565 缓冲即可。
- 不要手工修改 CubeMX 自动生成的 `stm32f4xx_hal_conf.h`、`main.h`、`gpio.c` 或 `.ioc` 以“启用 SPI”；应在 CubeMX 中配置后再生成代码，并且只在 `USER CODE` 区加入业务调用。

## 4. CubeMX 配置步骤

1. 打开 `RTT_elog_DMA_UART_ring_project.ioc`，启用 `SPI1`。
2. 选择 `Transmit Only Master`（若界面没有该选项，则选 Master，并只连接/使用 SCK 和 MOSI）。不要启用硬件 NSS，也不要为未接线的 MISO 增加功能需求。
3. 指定 PA5 为 `SPI1_SCK`、PA7 为 `SPI1_MOSI`；PA4、PA6、PB10、PA1 配为普通推挽 GPIO 输出。
4. SPI 参数设为：8-bit、MSB first、Software NSS、CPOL=High、CPHA=2nd Edge（SPI Mode 3）。这是参考工程的已用组合。
5. 本工程 APB2 为 100 MHz。首版预分频选 `/4`，SPI 时钟为 25 MHz，位于接线说明建议的 10--40 MHz 区间内。屏幕稳定后如需提高刷新速度，再用示波器确认信号质量并评估更高频率。
6. 初版不要勾选 SPI DMA。后续需要 DMA 时，在 CubeMX 为 SPI1_TX 选择空闲的 `DMA2 Stream3 / Channel 3`，Normal、Memory-to-Peripheral、Byte、Memory Increment。重新检查 USART1 的 Stream2/7 没有被改动。
7. 生成代码后，确认出现 `Core/Inc/spi.h`、`Core/Src/spi.c`，并在 `main.c` 的外设初始化序列中出现 `MX_SPI1_Init()`。该调用必须位于 `app_system_init()` 之前。

背光首版配置为 PA1 GPIO、上电默认关。首次执行完 `st7789_init()` 并写入纯色后，再逐次切换 PA1 验证亮/灭极性。确认有效电平后，定义 `LCD_BACKLIGHT_ON_LEVEL` 宏固定极性。不要把 PA1 配成 TIM2_CH2：本工程已把 TIM2 用作 HAL 时基。需要 PWM 调光时，优先评估 PA1 的 `TIM5_CH2`。

## 5. 推荐的软件分层

先完成最小驱动，再把显示接到采集数据。PC 串口只保留控制命令的**接收**能力，不再向 PC 回传控制应答、周期报告或单次采样报告。目录与职责建议如下：

```text
PC ──USART1 RX/DMA──> 01_APP/app_communication ──> controlQueue ──> 01_APP/app_control
                                                                        │
                                                                        └──> 01_APP/app_acquisition
                                                                                   │
                                                                                   └──按值复制──> displayQueue ──> 01_APP/app_display
                                                                                                             │
                                                                                                             └──> 03_Platform/platform_bsp/lcd
                                                                                                                          │
                                                                                                                          └──> SPI1 + GPIO
```

| 层级 | 建议新增内容 | 职责 |
| --- | --- | --- |
| `03_Platform/platform_bsp/lcd/` | `platform_st7789.c/.h` | 命令、数据、窗口、填充、字符位图、背光；不含采集业务 |
| `04_Impl/impl_mcu/` | 后续 `impl_platform_spi.*` | 只在需要 DMA、互斥或多个 SPI 设备时再抽象 HAL SPI |
| `01_APP/app_communication.*` | 保留并收缩为 UART 控制命令接收、解析和投递 | 只向 `controlQueue` 发布命令；禁止业务数据、控制应答经 UART TX 回传 |
| `01_APP/` | `app_display.c/.h` | 唯一 Display Task，接收数据快照并刷新页面 |
| `01_APP/app_ipc_types.h` | `app_display_snapshot_t` | 用按值拷贝的显示数据合同，禁止 Display Task 访问其他模块的 `static` 对象 |
| `01_APP/app_system.c` | 删除 `communicationOutboundQueue`；新增 Display Queue、Display Thread | 保留 UART 接收链路，建立显示任务依赖和构造顺序，不写绘图细节 |

第一版可以让 `platform_st7789` 直接使用 CubeMX 生成的 `hspi1`，因为工程还没有通用 SPI 抽象。只有需要 DMA 或多个 SPI 外设时，才补齐 `Platform SPI -> Impl SPI`；不要为了首个文字显示过早引入完整的多实例框架。

## 6. 驱动最小接口与初始化顺序

建议先提供以下接口：

```c
bool st7789_init(void);
void st7789_backlight_set(bool on);
void st7789_set_window(uint16_t x, uint16_t y, uint16_t width, uint16_t height);
bool st7789_fill_rect(uint16_t x, uint16_t y, uint16_t width, uint16_t height, uint16_t color);
bool st7789_draw_ascii(uint16_t x, uint16_t y, const char *text,
                       uint16_t foreground, uint16_t background);
```

底层发送规则固定如下：

```c
static void st7789_write_command(uint8_t command)
{
    HAL_GPIO_WritePin(LCD_DC_GPIO_Port, LCD_DC_Pin, GPIO_PIN_RESET);
    (void)HAL_SPI_Transmit(&hspi1, &command, 1U, 100U);
}

static void st7789_write_data(const uint8_t *data, uint16_t length)
{
    HAL_GPIO_WritePin(LCD_DC_GPIO_Port, LCD_DC_Pin, GPIO_PIN_SET);
    (void)HAL_SPI_Transmit(&hspi1, (uint8_t *)data, length, 100U);
}
```

`CS` 在整次命令/数据事务开始前拉低、结束后拉高；`DC=0` 表示命令、`DC=1` 表示参数或像素数据。窗口函数必须把逻辑坐标统一转换为 GRAM 坐标：

```text
CASET (0x2A): x + 0 .. x + width  - 1
RASET (0x2B): y + 20 .. y + height - 1 + 20
RAMWR (0x2C): 后续连续发送 RGB565，高字节在前
```

参考驱动为 240x280 面板使用 `Y_OFFSET=20`。这个偏移必须集中在 `st7789_set_window()`，不要像旧参考代码那样只在 `LCD_Fill()` 中加偏移、而 `LCD_DrawPoint()` 漏加偏移，否则不同 API 会出现 20 像素错位。

初始化顺序：

1. 背光关闭，CS 拉高，DC 拉高，RST 拉高。
2. CS 拉低；RST 拉低至少 100 ms，再拉高至少 100 ms。
3. 发送 `0x11`（Sleep Out），等待至少 120 ms。
4. 按 `OV_Watch/BSP/LCD/lcd_init.c` 的 ST7789 初始化表发送寄存器参数；其中方向使用 `0x36, 0x00`，像素格式使用 `0x3A, 0x05`，开启反色使用 `0x21`，显示开启使用 `0x29`。
5. 用 `st7789_fill_rect(0, 0, 240, 280, BLACK)` 清屏，再写入 `WELCOME` 或四色条。
6. 确认像素位置和颜色正确后，再打开背光。

`HSD1.69+ST7789T3_IPS驱动.txt` 只是另一组控制器命令片段，其 `0x3A` 参数和部分电压/伽马参数与可运行的 `OV_Watch` 驱动不同。首版以完整的 `OV_Watch/BSP/LCD/lcd_init.c` 初始化表为基线，不能混拼两份初始化序列。

## 7. 从采集数据刷新页面

当前数据已经由 `service_acquisition_sample()` 生成，并在 `app_acquisition.c` 中复制为 `app_acquisition_data_t`。目标架构中不再存在 Communication Outbound Queue，也不再将采样数据格式化后经 USART1 TX 发送到 PC。显示不能复用控制命令队列；它必须有独立的 `displayQueue`。

应在 `app_acquisition_config_t` 中将原 `communicationQueue` 替换为独立的 `displayQueue`，并在周期采样、单次采样均成功后分别投递一份 `app_display_snapshot_t`。推荐从现有的 `app_acquisition_data_t` 复制所需字段：

```c
typedef struct
{
    float temperatureC;
    float humidityPercent;
    int16_t accelX;
    int16_t accelY;
    int16_t accelZ;
    uint32_t sampleSequence;
} app_display_snapshot_t;
```

Display Task 使用低于 Acquisition/Communication 的优先级，阻塞等待 `displayQueue`。收到新快照后只刷新发生变化的文本区域；采集周期当前为 2 s，因此不需要动画、LVGL 或全屏反复清屏。队列投递使用非阻塞方式：屏幕繁忙时允许丢弃旧帧，绝不能阻塞传感器采集或 UART DMA 环形缓冲处理。

任务改造清单如下：

| 现有对象 | 调整后职责 |
| --- | --- |
| `app_communication` / Communication Task | 保留 UART RX、命令帧解析和向 `controlQueue` 投递 `START`、`STOP`、`ONCE` 等控制命令；删除 `app_communication_outbound_message_t` 的格式化、出队和 UART TX 发送。 |
| `app_control` / Control Task | 保持控制状态机与向 Acquisition Task 的控制消息投递；控制结果通过下一帧屏幕状态或采样数据显示，不再回传 PC。 |
| `app_acquisition` / Acquisition Task | 成功采样后向 `displayQueue` 发布快照，替代原先向 `communicationOutboundQueue` 发布周期/单次报告。 |
| `app_display` / Display Task（新增） | 独占 LCD，显示传感器数据、采样序号和必要的采集状态；不读取 UART，不执行命令解析。 |
| `service_uart`、UART DMA 环形缓冲和 `platform_uart` | 保留，服务于 PC 下发控制命令；本次不删除 USART1 RX/DMA。 |
| `service_log` / RTT elog | 保留为调试日志，不属于 USART1 的 PC 业务数据上报。 |

`app_system.c` 中不再创建 `g_communicationOutboundQueue`，`app_ipc_types.h` 中与 PC 上报专用的 `app_communication_outbound_message_t` 可删除。`app_communication` 的初始化参数、Communication Task 的循环以及 `service_uart` 的调用点都应移除 TX/应答相关成员和分支，但必须保留 RX 与命令解析路径。

推荐的首个页面：

```text
SENSOR MONITOR
T:  25.3 C
H:  48.6 %
AX:  -1234
AY:    256
AZ:  16320
```

屏幕驱动的坐标和像素数据只由 Display Task 使用；ISR、HAL SPI 回调、UART 回调和 Acquisition Service 中都不允许直接调用绘图 API。英文/数字先使用参考 `lcdfont.h` 的 ASCII 点阵或一个小型自有字库。不要依赖 `printf("%f")`：Keil 的 MicroLIB 默认可能未启用浮点格式化，且浮点格式化会增大代码和栈开销。温湿度可先转换为固定一位小数的整数后再显示。

## 8. DMA 演进与 RTOS 规则

在 25 MHz SPI 下，一帧 240x280 RGB565 的纯像素数据约为 134400 字节，理论传输时间约 43 ms；文本局部刷新远小于此值。因此首版 PIO 传输足够验证数据页，DMA 只用于后续大面积填充。

增加 SPI DMA 时遵守以下规则：

- 使用与 USART1 不冲突的 DMA2 Stream3/Channel3，并确认 CubeMX 生成的 IRQ、DMA handle 和 `__HAL_LINKDMA()` 都正确。
- Display Task 是唯一的 SPI1 提交者。若将来允许其他任务访问 SPI1，使用互斥量保护“CS 拉低到 DMA 完成”的完整事务。
- DMA 完成回调只释放信号量/任务通知；真正的窗口切换、下一块像素和页面业务逻辑都在 Display Task 中执行。
- 不在 ISR 中调用 `HAL_SPI_Transmit()`、绘图、`printf`、动态内存或阻塞延时。
- 行缓冲用 `static uint16_t lineBuffer[240]`，DMA 期间不得改写；不把 480 字节缓冲放到任务栈。

## 9. 验证顺序

按以下顺序验证，任一步失败都先停在该层排查：

1. **上电前**：确认连接器供电与 GND，无触摸引脚短接；确认 PA4/5/6/7、PB10、PA1 没有被其他板级功能占用。
2. **CubeMX/编译**：SPI1 生成成功，USART1 的 DMA2 Stream2/7 保持原映射，Keil 加入新增的 `.c` 文件后零编译错误。
3. **总线**：RST 有低--高脉冲；CS 仅在事务期间为低；DC 在命令与数据间切换；PA5 有 25 MHz、Mode 3 时钟，PA7 有数据。
4. **显示最小闭环**：黑、红、绿、蓝全屏或色条；确认没有 20 像素纵向偏移、镜像或颜色错位。
5. **文字**：显示 `WELCOME`、整数和一位小数温湿度；确认字符不重影。
6. **数据链路**：从 PC 分别下发一次采集、开始周期采集和停止命令；确认命令被接收并生效，采集结果只更新屏幕，串口监视器没有业务数据或控制应答输出。连续运行 30 分钟，确认 UART 接收、RTT 日志和传感器采集未退化。
7. **DMA（后续）**：只在前六步稳定后测 DMA 刷新；确认 Stream3 完成中断、Display Task 唤醒和 UART DMA 都持续正常。

## 11. 一句话结论

该板应以 PA5/PA7 的 SPI1 输出驱动 ST7789，以 PA4/PA6/PB10/PA1 控制 CS/DC/RST/背光；首版用单一 Display Task + 独立数据队列 + 行缓冲完成 2 秒级传感器数据显示。USART1 RX/DMA 和 Communication Task 只保留 PC 下发控制命令的能力，不再向 PC 发送业务数据或控制应答；触摸与 SPI DMA 都留到显示基本闭环稳定之后。
